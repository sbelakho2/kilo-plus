# JetBrains split-mode scaffold (Kilo+)

The JetBrains side of the Kilo+ split-mode design. The frozen **JetBrains
7.1.2 Kotlin frontend** stays untouched; this scaffold replaces only the part
the 7.1.2 process manager used to own (launching the old CLI) with a manager
that launches the **Kilo+ binary** (`kilop-cli serve --port 0`) and speaks
the frozen v7.5.6 wire contract.

## How the frozen 7.1.2 frontend drops in

1. Keep `:shared` and `:backend` exactly as they are — they are the wire
   boundary and the process boundary, and both are verified against the real
   daemon by `compile-and-smoke.sh`.
2. Replace `frontend/src/main/kotlin/dev/kilop/frontend/PlaceholderFrontend.kt`
   with the frozen 7.1.2 plugin sources (chat rendering, tool panels, model
   picker). The only integration point the frontend needs:
   `dev.kilop.backend.BackendProcessManager` (start/stop/health/createSession/
   sendMessage/sessionState/listMessages). All session state for rendering
   comes from those responses — nothing else is read.
3. The plugin resolves the Kilo+ binary path (bundled or user-selected) and
   passes it to `BackendProcessManager`; the daemon's data dir is the
   plugin's sandbox-visible dir.

## Modules

| Module | Contents |
| --- | --- |
| `:shared` | `dev.kilop.shared` — the v7.5.6 wire contract as plain Kotlin data classes. Zero dependencies (no kotlinx.serialization, no okhttp): hand-built request JSON + a tiny recursive-descent JSON reader for responses. |
| `:backend` | `dev.kilop.backend` — `BackendProcessManager`: launches the binary, parses the startup line, Basic auth via `java.net.http.HttpClient`, bounded stdout drainer, SIGTERM-then-forcible stop. |
| `:frontend` | `dev.kilop.frontend.PlaceholderFrontend` — documents where the frozen 7.1.2 frontend plugs in. |

## Wire contract (frozen, do not invent)

- Startup line: `kilo server listening on http://127.0.0.1:<port>` on stdout,
  nothing else (`compat/kilo-v756/startup_line.json`).
- Auth: `Authorization: Basic base64("kilo:" + KILO_SERVER_PASSWORD)`,
  64-hex password generated by the frontend
  (`compat/kilo-v756/basic_auth.json`).
- Routes: `POST /session`, `GET /session/{id}`,
  `POST /session/{id}/message`, `GET /session/{id}/message?limit=5`,
  `GET /global/health`. Exact shapes in
  `crates/protocol/src/v756/wire.rs` (camelCase, `sessionID`/`messageID`/
  `providerID`/`modelID` strings). `Model` (`id`/`providerID`) is the
  session-create shape; `MessageModel` (`providerID`/`modelID`) is the
  message-send shape — they are intentionally distinct types.

## Verification

No Gradle, no network — plain kotlinc against the real daemon:

```bash
bash apps/jetbrains/compile-and-smoke.sh
```

This builds `kilop-cli` if missing, compiles shared+backend+test+frontend
with `kotlinc` (kotlin-test.jar comes from the compiler's own lib dir), and
runs `BackendSmoke <binary>`: fixture assertions (startup-line regex, Basic
auth base64, request JSON, response parsers, missing-binary failure) then a
full daemon flow (start → health → create session → send message → state
settles → list messages → stop), printing PASS/FAIL per step and exiting
0/1. The smoke sends a message with no provider configured; the session lands
on `failed_recoverable`, which the smoke accepts alongside
`ready_for_next_turn` (it proves the wire, not the provider).

## Notes / deviations

- `ToolPart.input` is raw JSON embedded verbatim (no schema needed for
  arbitrary tool payloads).
- The Gradle files exist for the future real plugin build (toolchain 17).
  They are not used by the verification script.
- CI (ubuntu job) installs kotlin via apt. The Debian `kotlin` package is
  1.3.31, which cannot read class files from JDK >= 16; when the default JDK
  is too new, `compile-and-smoke.sh` retries the compile with the newest
  installed JDK <= 12 from `/usr/lib/jvm`. macOS CI skips this step (brew
  kotlin is slow; the wire is platform-independent).
